# PixelFrame — Claude Handoff

> Last updated: 2026-08-26

## What This Is
PixelFrame is a web-based pixel art editor — full drawing tools (pencil/eraser/bucket/eyedropper/color-eraser/line/rect/ellipse), marquee selection with transform handles, layers, PICO-8 palette with auto ramps, PNG import/export, IndexedDB autosave, multi-tab editing, a sprite kits panel for building character pieces (helmets, bodies, arms, legs), and an animation timeline (frames, cels, playback, onion skinning) with GIF / sprite-sheet / PNG-sequence export. Was called "Pixel Studio" until 2026-05-11.

## Architecture Notes
- App entry: `src/app/page.tsx` + `src/app/layout.tsx` (metadata title is "PixelFrame")
- Branding: `public/logo.png` rendered in the TopBar (20px, `image-rendering: pixelated`); `src/app/icon.png` + `apple-icon.png` auto-served by Next.js as favicon / touch icon
- Animation: `src/components/Timeline.tsx` (frames, cels, playback, onion skinning); export lives in `src/lib/export.ts` + `src/lib/gif.ts` (GIF encoder)
- State: `src/lib/store.ts` (Zustand store — layers, canvas dims, tools, selection, undo/redo, tabs, kits)
- Persistence: `src/lib/persist.ts` — IndexedDB key is `pixelframe:doc` (was `pixel-studio:doc` before — old autosaves in users' browsers won't load)
- TopBar (`src/components/TopBar.tsx`) renders brand label + New/Import/Export
- Tabs: `src/components/TabBar.tsx` + `Editor.tsx` for multi-doc switching
- Kits: `src/components/KitsPanel.tsx` reads from `public/kits/*.json` (helmets, bodies, arms, legs, manifest); kit JSON is generated by `scripts/generate-helmets.mjs` etc.
- Kit save route: `src/app/api/kits/save/route.ts` — per-kit in-process mutex, atomic `.tmp` + rename writes, w/h capped at 512 (matches `resizeCanvas`), palette capped at 256 entries with typeguard. Dev/self-hosted only — won't run on Vercel (read-only FS).
- Dialogs: `src/lib/dialog.ts` + `src/components/DialogHost.tsx` for branded modal stack
- PNG import: `src/lib/import.ts` — sharp (nearest-neighbor) or smooth sampling, source cap 512px
- Canvas is locked-centered: zoom only, no pan (pan persistence kept loading canvases at top-left)
- Drawing tools: `src/lib/pixels.ts`; types: `src/lib/types.ts`

## Collaborator Workflow (drudzins1)
drudzins1 has **read-only** access on the main repo. Branch protection isn't available on free private repos, so the agreed flow is:
1. drudzins1 forks `Cougler/PixelFrame` → their fork is private to them
2. drudzins1 pushes branches to their fork
3. drudzins1 opens cross-repo PRs into `Cougler/PixelFrame:main`
4. Aaron reviews + merges

For the bidirectional review flow (Aaron reviews Danny's PRs and vice versa via Danny's own Claude instance), see `memory/feedback_pr_review_flow.md` — natural-language phrases like "check the PR submitted by the other person" → checkout + brief; "merge it" → squash-merge + back to main.

Note: a **repo ruleset** enforces "changes must be made through a pull request" / `REVIEW_REQUIRED` (confirmed 2026-08-25 — direct pushes to main by the owner print a "Bypassed rule violations" notice). Aaron's own PRs merge with `--admin` override; Danny's PRs get a formal Approve via `gh pr review N --approve` before squash-merging. Manage it under Settings → Rules → Rulesets if it should change.

**Stacked-PR gotcha** (hit on #5/#6): squash-merging the base PR and deleting its branch auto-closes the stacked PR and leaves it conflicting. Fix: restore the deleted base branch ref (`git push origin <sha>:refs/heads/<branch>`), reopen the PR, retarget it to main, merge main into the PR branch resolving conflicts with the branch side (its tree already contains the final content), then squash-merge.

If drudzins1 ever needs more access, can be upgraded with `gh api -X PUT /repos/Cougler/PixelFrame/collaborators/drudzins1 -f permission=push` — but the whole point of read-only is to force PRs.
